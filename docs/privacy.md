# Privacy Notes

- Weather uses device location when permission is granted.
- Sunrise, sunset, civil twilight, and the Road trip daylight heads-up are calculated on the Mac from the device location (or the approximate IP location) and the current date. They use no network request and no weather service, and nothing is sent anywhere.
- External IP lookups use FreeIPAPI.
- External IP location display is enabled by default for new installs and can be disabled in Settings.
- When both signals are available, the dashboard header can show device location and IP-based location side by side for comparison.
- Local Info uses resolved location context plus public data sources. Public holidays use Nager.Date, school holiday coverage uses OpenHolidays only when a confident regional match is available, Europe price signals use Eurostat country-level indices (36 European countries, and the United Kingdom's overall level), and US 1-bedroom rent uses HUD USER plus the US Census Geocoder when the user adds a HUD token and current location is available.
- Planned trips (country, dates and an optional note) and the home country, chosen in the Trip Planner and Settings, are sensitive and are stored only on the Mac with the other settings. They are never sent anywhere and never part of analytics. The Trip Planner's preview, its Schengen, stay-allowance and tax-day what-if, and the Next Trip Siri and Shortcuts answer are computed on the Mac from them, the days saved for visited places, and tables bundled with the app.
- The departure checklist of a planned trip (which suggested items you ticked, and the items you added yourself, up to 30 of up to 120 characters) is stored locally with the trip on the Mac and is never sent anywhere or part of analytics.
- The jet-lag nudge keeps a short history of the Mac's time zone changes (the last 10: date, time zone identifier and UTC offset) locally in `time-zone-shifts.json` in the app's support folder. It is computed on the Mac, never sent anywhere or part of analytics, and cleared together with the visited places.
- The map in a trip's preview loads Apple Maps tiles for the framed destination region when you open the trip, as any map in a Mac app does; the region comes from country bounds bundled with the app, and nothing about the trip, your dates or the checklist is added to the request. Tapping an embassy marker opens Apple Maps with a search for that mission. Offline the map stays blank.
- Looking up public holidays and the travel advisory for a planned trip sends only the destination's country code (the holiday source also gets the year), with no dates, note, citizenship or location. Offline, or in Low Data mode, nothing is requested and only what is saved is shown. Comparing prices with home asks Eurostat for the price-level indices of the destination and the home country and sends only those two country codes; the result is cached on the Mac for a week.
- Project time tracking stores projects, exact time entries, and runtime tracking state locally on the Mac.
- Project time tracking interruption events are also stored locally on the Mac and are used only for local summaries, focus-loss estimates, and exports.
- The dashboard Allocate menu for project time tracking is populated from that same local project and tracking data.
- Project time tracking exports go only to the system clipboard when the user explicitly chooses to copy a monthly report.
- Non-production and development builds use a separate local time-tracking storage namespace from the live app.
- Keep Awake is local-only and sends nothing anywhere. It asks macOS for a standard power assertion and stores only the Keep Display On and Keep Awake With Lid Closed preferences; the running session itself is not saved, and macOS releases the assertion when the app quits.
- Keep Awake With Lid Closed uses a privileged helper (a launchd daemon the user approves once in System Settings > General > Login Items) that runs as root. It does exactly one thing: it turns the global macOS "disable sleep" setting on while a session runs and restores the previous value afterwards. It has no network access, accepts connections only from Nomad Dashboard signed by the same developer team, and keeps no data except a tiny local journal (the setting's previous value and the session deadline) in `/Library/Application Support/<helper label>/` that it deletes when the session ends; the journal lets it restore the setting after a crash or restart. Nothing about it is sent anywhere or part of analytics.
- Visited places, chronological visited-place events, and country-day travel history are stored locally on the Mac and can be cleared by the user.
- Visited history prefers device location when available. IP geolocation is stored for visited history only when device location cannot be resolved for that capture.
- Chronological visited-place events include resolved city and country context, approximate coordinates when available, source type, and first and last local observation timestamps so the app can draw a yearly travel path.
- Country-day history may estimate missing days between two known countries using surrounding captures.
- Country-day year and month summaries can be copied to the clipboard as plain text when the user chooses to export them.
- Country-day entries can be added, edited, or restored by the user; these manual changes are saved locally on the Mac.
- Nomad Life workplace collection is off until enabled. When enabled, it uses authorized device-location samples only to group stationary visits locally; IP address and VPN state are never used to identify a venue.
- Nomad Life may ask Apple MapKit for a nearby coworking or café suggestion. Suggested venue names remain unconfirmed until the user confirms or edits them.
- Nomad Life diary entries and preferences, including the chosen home time zone and local work-readiness context, are stored locally on the Mac.
- Opening Google Maps for a diary entry is an explicit user action and sends the selected map request to Google Maps.
- Quiet connection alerts are opt-in. They use connection, VPN, charging state changes, and Data Guard cap warnings with cooldowns and configured quiet hours; alert text does not include location or IP address.
- Emergency numbers shown on the Emergency Care and Local Info cards and in Offline essentials come from a table bundled with the app. They are looked up offline from the current country code; nothing is sent anywhere for them.
- Citizenship, chosen in Settings under General, is sensitive and is stored only on the Mac with the other settings. It is used only to find your embassy and your foreign ministry's consular line, is compared with data bundled in the app, is never sent anywhere, and is never part of analytics.
- The Your Embassy card and Offline essentials use a table of embassy and consulate locations (Wikidata, CC0) and foreign-ministry contact details bundled with the app. Lookups run offline from the current country code and device coordinate; nothing is sent anywhere for them.
- Opening a mission in Apple Maps, a mission or ministry website, or a travel registration service is an explicit user action and sends that request to Apple or to the website. Copying a phone number or address only uses the system clipboard.
- Stays & Visas (days in the current country, stay allowances, the Schengen 90/180 count and this year's days per country for tax residence) is computed on the Mac from the country-day history saved locally for visited places. Stay allowances, the thresholds and the results stay on the Mac with the other settings, are never sent anywhere, and are never part of analytics. Review days opens the local Visited Map. The card is off while `Save visited places locally` is off.
- The arrival briefing is composed locally when a new country is noticed, from the country-day history, the dashboard's current data and tables bundled with the app (emergency numbers, embassies, driving side, plugs, currency, local rhythm). Nothing is sent anywhere for it, and the country you last dismissed it for is stored only on the Mac.
- Local rhythm dates (Ramadan, Lunar New Year and similar) are calculated on the Mac from the current country; no network request is made for them.
- Air quality uses Open-Meteo's air quality service. A location rounded to about 11 km (the grid point, not the exact device location) is sent, with no account or identifier, only while `Use current location for weather` is on, and it can be turned off under Settings, Weather & Local, Air quality. The result can be kept in the bounded offline cache.
- The UV index comes from WeatherKit together with the weather and uses the same location the weather already uses.
- Siri and Shortcuts answers (emergency number, status, nearest embassy, daylight) are built on the Mac from the dashboard state the app already holds and the data bundled with it. Siri and Shortcuts receive only the answer sentence, and the Set Travel Profile action only changes the local setting. Nomad Dashboard sends nothing anywhere for them.
- The desktop widgets (Glance, Safety, Daylight) read a small file the app keeps in an App Group container shared only by the app and its widget extension (same developer team) on the Mac. It holds the verdict, the place name, up to two heads-up titles (which can name a stay allowance, the Schengen counter or a tax-residence day count for the current country, such as "Schengen: 8 of 90 days left", worked out on the Mac from the days it records; the days themselves are not in the file, and a Schengen title only shows that the 90-day rule applies to you, not which citizenship you hold), the emergency number and country name, the nearest embassy name and consular hotline when a citizenship is chosen, today's sunrise and sunset, and when it was saved. It does not hold the IP address, coordinates, or citizenship codes, and it is replaced as the dashboard refreshes. Nothing in it is sent anywhere. Builds without the App Group (unsigned development builds) write no file.
- A widget is visible on screen: anyone who can see your desktop or Notification Center can see the place, emergency number, consular line and any stay or Schengen heads-up it shows.
- Data Guard stores Wi-Fi network names (SSIDs), remembered metered network preferences, and cumulative byte totals locally on the Mac. This data is not uploaded.
- Travel advisory uses Smartraveller and is enabled by default.
- Smartraveller advisory fetches use direct HTTPS requests first and may retry through a hidden WebKit-backed page load when the direct transport path stalls.
- After a destination is matched, Smartraveller may also fetch that destination page directly to extract a short advisory reason sentence and keep a source link for `More details`.
- Weather alerts use WeatherKit and stay off until you enable them.
- Regional security uses ReliefWeb and stays off until you enable it.
- Advisory and regional security scope use the current country plus bordering countries when country context is available.
- External lookups are cached to reduce noise, latency, and battery impact.
- Explore Cities can automatically follow the current city from existing dashboard location context (device location first, approximate IP location as fallback). `Follow my city` is on by default and can be turned off in the explorer. It does not request additional location permission.
- Automatic city matching uses Nomads.com's public city directory locally, first by city and country, then by distance within 50 km in the same country. Device coordinates are not sent to Nomads.com. Only a matched city slug is sent to retrieve city details; manual searches send the entered country, budget, and internet filters. Nomads.com sees the connection's IP address. Travel history, workplace entries, and account credentials are not sent.
- The directory and the last automatic result (including a no-match result), normalized city identity, and check time are stored locally so the same city is not checked again after dashboard refreshes or app restarts. There is no scheduled refresh; a different city or explicit Retry permits another check. Saved data may become out of date while staying in one city. Corrupt saved data is preserved and reported.
- Manual searches and city details additionally use a bounded six-hour memory cache and shared request budget. Destination photos load only in the explorer from image URLs supplied by Nomads.com, including its resizeapi.com image service; those hosts see normal image requests and the connection's IP address. Source, city, meetup, and Join Nomads.com links open Nomads.com in the browser only when clicked. The join link uses the public `?join=nomads` destination; it does not create an account or send local travel data.
- Hidden menu-bar background refreshes run at a slower cadence than the open dashboard to reduce battery impact.
- A bounded local cache retains selected remote dashboard content for temporary offline use. It intentionally excludes live network, latency, battery, diagnostics, and metric-history data.
- Anonymous TelemetryDeck analytics are enabled by default.
- `app_install_first_seen`, `app_launch`, and `app_background_active_day` are always sent to estimate install, launch, and background reach.
- `app_active_day`, `primary_ui_opened`, and `settings_opened` follow the in-app `Share anonymous analytics` setting.
- Analytics payloads include only app name, version, build number, distribution channel, and app type.
- Analytics do not include usernames, emails, locations, IP addresses, file names, or document titles.
- Release and update infrastructure should avoid embedding secrets in the repo.

If the workplace diary cannot be decoded or read, Nomad preserves the original file and pauses collection rather than replacing it with an empty diary.
